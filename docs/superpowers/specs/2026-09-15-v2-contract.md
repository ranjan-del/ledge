# Ledge v2 contract: planning, session memory and the panel

Date: 2026-09-15. Extends `2026-09-14-ledge-design.md`. Nothing here removes anything that
already works; every field and section below is optional, so a v1 task file stays valid.

## 1. Why

Four gaps came out of using the panel for an evening:

- The floating button disappears when you switch applications, so the thing that is supposed
  to always be there is not.
- The panel is full height, which is more space than the content needs and makes it feel like
  an application window rather than a panel.
- Nothing records *when* you intend to work on something, so a list of tasks cannot answer
  "what is on for today".
- Nothing carries what happened in a work session, so the assistant starts each session with
  the checklist but none of the reasoning behind it.

## 2. Task file: three additions

```markdown
---
id: release-watch-banner
title: Release watch banner for stale tabs
status: current            # current | backlog | done
order: 1
repo: ~/code/thinktac-india-production/apps/admin-web
planned: 2026-09-18        # NEW, optional. The day you intend to work on this.
sessions:
  - b13e8b5e
created: 2026-09-15T21:04:00+05:30
updated: 2026-09-15T23:04:00+05:30
---

## Requirement

Short statement of what has to be true when this is finished.

## Checklist

- [x] Investigated why open tabs break after a deploy
- [ ] Build step that writes version.json

## Notes                                          <!-- NEW, optional -->

### 2026-09-15
Decided to poll a version file rather than use a service worker, because the app already
fetches a static config file the same way. Chunk load errors are the safety net.

## Plan                                           <!-- NEW, optional -->

1. Write version.json at build time
2. Poll it on an interval and on window focus
3. Show the banner, reload only when idle
```

### Field and section rules

| Name | Kind | Rule |
|---|---|---|
| `planned` | frontmatter, optional | Calendar date, `YYYY-MM-DD`, no time, no zone. Parsing a malformed value must not break the file: drop the field and record it as a parse warning. |
| `## Notes` | body section, optional | Dated `### YYYY-MM-DD` subsections, newest last. The assistant appends to today's subsection, creating it if missing. Free prose. This is the session memory. |
| `## Plan` | body section, optional | An ordered list of steps, written before work starts. Distinct from the checklist: the plan is the intent, the checklist is the tracking. |

Body section order in a serialized file is fixed: Requirement, Plan, Checklist, Notes, then
any other content. A file whose sections are in a different order must still parse, and is
rewritten in this order when saved.

## 3. Core API additions

Additive only. Existing signatures do not change.

```ts
export interface Task {
  /* ...all existing fields... */
  planned?: string;        // YYYY-MM-DD
  plan: string[];          // ordered steps, [] when the section is absent
  notes: NoteEntry[];      // newest last, [] when the section is absent
}

export interface NoteEntry {
  date: string;            // YYYY-MM-DD
  body: string;            // markdown, trimmed
}

/** Tasks planned for the given day, or overdue and still not done. */
export function plannedFor(tasks: Task[], day: string): { today: Task[]; overdue: Task[] };

/** Appends text to today's note subsection, creating it when absent. */
export function appendNote(task: Task, text: string, day?: string): Task;

/** Replaces the plan steps. */
export function setPlan(task: Task, steps: string[]): Task;
```

`TaskStore` gains `setPlanned(id, day | undefined)`, `addNote(id, text)` and
`setPlan(id, steps)`. Every one of them is a read, a pure transform and a save.

## 4. CLI additions

| Command | Effect |
|---|---|
| `ledge plan <id> "step" "step" ...` | Replace the plan steps |
| `ledge note <id> "text"` | Append to today's notes |
| `ledge when <id> <YYYY-MM-DD\|today\|tomorrow\|none>` | Set or clear `planned` |
| `ledge today` | Tasks planned for today, plus overdue ones, plus current tasks |

`ledge current --context` gains the plan, today's note and the planned date, still capped at
40 lines. This is what the assistant reads at the start of every session.

## 5. Plugin additions

`/ledge` gains three subcommands: `plan`, `note`, `when`. The command body instructs the
assistant to do the following without being asked:

- On starting work, if the task has no plan, write one before editing code.
- When a decision is made or something surprising is found, append a note. Notes are for
  reasoning and dead ends, not a restatement of the checklist.
- Before context is compacted and at the end of a session, append a note covering what was
  done, what is left, and anything the next session needs to know.

The `Stop` hook already links the session id. It now also reminds the assistant, through the
session context on the next start, that notes exist and should be read.

## 6. Panel behaviour and layout

| Item | Decision |
|---|---|
| Height | 60 percent of the work area height, minimum 420 px, maximum 900 px. Vertically centred on the button. |
| Width | 380 px, unchanged. |
| Button visibility | Must stay on screen when another application is activated, when switching with the application switcher, and on every Space including over a full screen application. |
| Panel dismissal | Hides when it loses focus unless pinned, unchanged. |

## 7. Home view

The Current tab is the home view. It answers, in this order:

1. What is on for today: tasks planned for today, and overdue ones marked as such.
2. What I am working on: current tasks in priority order, each showing progress and live git state.
3. What needs attention: a single line linking to Pending when repositories have unpushed or
   uncommitted work.

Adding a task must be possible from the home view in one interaction, with title only, and
everything else optional.
